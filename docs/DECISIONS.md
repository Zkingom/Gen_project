# 设计决策记录

每行格式：**决定** — 原因 — 备选方案。

## 环境 / 流程

- **使用合成数据跑通全流程** — 云端环境的出站代理拒绝访问 data.binance.vision / fapi.binance.com（HTTP 403）— 备选：无（真实下载代码已写好，见 PROGRESS.md 切换说明）。

## Phase 1 数据层
- **只做日线，不做小时线** — 横截面因子研究以日频为主，日线数据量小、易于讲清；小时线下载只需把 `1d` 改成 `1h`，但面板和对齐规则需另行设计 — 备选：同时支持 1h。
- **日线用开盘日期 d 标识，"日期 d 的信息"= d 收盘（d+1 00:00 UTC）时可得的信息** — 与 Binance 文件约定一致，且使因子、股票池、调仓的时点统一 — 备选：用收盘日期标识（容易与资金费归属混淆）。
- **资金费结算时间在 (d 00:00, d+1 00:00] 归属日线 d** — 这样日线 d 的价格收益与资金费描述同一段持仓（d 开盘建仓到 d 收盘），回测可以直接相加 — 备选：[d 00:00, d+1 00:00)（会把建仓瞬间那次结算算进来、漏掉收盘那次）。
- **资金费时间戳四舍五入到整分钟** — 真实数据有几毫秒抖动，取整后才能去重、对齐 — 备选：截断到秒。
- **存储层不填充缺失价格（保留 NaN）；坏 K 线置 NaN 而不删除** — 填充会伪造"零成交、零波动"的日子，扭曲波动率/成交额因子 — 备选：ffill 价格、成交量补 0。
- **收益率分母用"上一个有效收盘价"（最多回溯 3 天）** — 缺口期间的真实涨跌会记到缺口后第一天，回测不会漏算盈亏 — 备选：pct_change（缺口后收益为 NaN，盈亏丢失）。
- **每个标的一个 parquet 文件，数值列 float32** — 按标的读取、内存与需求成正比；float32 内存减半 — 备选：按月分区的大表（跨标的查询更快，但单标的更新麻烦）。
- **标的列表来自 S3 目录列举而不是交易所"当前交易对"接口** — 前者包含已下架合约，避免幸存者偏差 — 备选：exchangeInfo 接口（只有当前在交易的合约）。
- **股票池：上市满 60 天、当日可交易、过去 30 天平均成交额前 N 名；用到 d 收盘为止的数据** — 在 d 收盘决定股票池并同时调仓，这些信息此时都已可得 — 备选：再 shift(1) 只用 d-1 及以前（更保守，但与因子时点不一致）。
- **下架判定：最后一根 K 线早于全局数据末日 3 天以上** — 只用于描述数据，不用于筛选 — 备选：读交易所下架公告（无公开历史接口）。
- **合成数据植入弱信号（反转、动量、资金费率负向预测）并模拟"死亡币"** — 让评估、回测、合成有可观察的结果，并能演示幸存者偏差；所有结论都标注"仅验证流程" — 备选：纯随机游走（所有因子 IC≈0，无法检验流程是否能识别信号）。

## Phase 2 因子库
- **8 个因子：reversal_5d、momentum_30d（跳过最近 5 天）、volatility_20d、volume_ratio_5_60、amihud_20d、pv_corr_20d、funding_level_7d、funding_change_7_30** — 覆盖价格/成交量/量价/资金费四类经典思路 — 备选：用市值类因子（加密货币缺可靠流通市值数据）。
- **用成交额相对变化代替换手率** — 没有流通量数据，换手率无法计算 — 备选：成交额绝对值（本质是规模因子，与流动性筛选高度重合）。
- **每个因子带一个"先验方向"，在看数据之前按文献/直觉确定** — 等权合成需要统一方向；用样本 IC 决定方向会引入过拟合 — 备选：用全样本 IC 的符号（属于样本内信息）。
- **因子输出在"当天无有效价格"处一律为 NaN** — 不能交易的标的不应有信号 — 备选：保留（会污染横截面排名）。
- **前视测试用两种方式：篡改未来（极端值/全 NaN）+ 截断数据重算** — 前者对应 CLAUDE.md 要求，后者直接检验"时点一致性"，两者互补 — 备选：只做一种。

## Phase 3 因子评估
- **标签 = 从 d 收盘持有到 d+h 收盘的复利收益；评估时因子 f(d) 与标签 d 配对** — 假设 d 收盘算因子并以收盘价成交，是日频研究的标准约定；执行延迟在 Phase 4 回测里可配置 — 备选：标签从 d+1 收盘开始（更保守，但 IC 会被低估）。
- **标签中下架/缺失日收益按 0 计（在最后可得价格平仓）** — 若让含下架日的标签变 NaN，暴跌下架的币会从评估中消失，形成幸存者偏差 — 备选：丢弃。
- **主看 RankIC，同时报告 Pearson IC** — 加密收益肥尾，单个极端值会主导 Pearson 相关 — 备选：只看 IC。
- **h>1 时 t 值用 n/h 作为有效样本数** — 相邻标签重叠导致 IC 自相关，直接用 n 会高估显著性；n/h 是简单易讲的近似 — 备选：Newey-West 调整（更精确但更难解释）。
- **分组回测：每天按股票池内因子排名分 5 组、组内等权、持有 1 天；LS = 第 5 组 − 第 1 组** — 最常见的教科书做法；因子已按先验方向调整，第 5 组为"预期最好" — 备选：市值加权（无市值数据）。
- **换手用两个指标：排名自相关 + 最高组成分换手** — 前者衡量信号稳定性，后者直接对应交易量 — 备选：只报一个。
- **横截面有效标的少于 10 个的日子不计算 IC** — 样本太少时相关系数噪音过大 — 备选：不设门槛。
- **完美因子只在 tests/ 里定义，并有测试检查因子库中没有它、因子源码不调用未来标签、没有负向 shift** — 满足 CLAUDE.md 要求 — 备选：无。

## Phase 4 带成本回测
- **按名义价值逐日记账（NAV + 每个标的的持仓名义价值），持仓随价格漂移，只在调仓日交易** — 能手算核对，且调仓频率降低时自然体现"权重漂移" — 备选：每天直接用目标权重乘收益（隐含每天免费再平衡，低估换手）。
- **成本 = 成交额 ×（taker 费率 + 滑点率），默认 0.05% + 0.05%** — Binance U 本位普通用户 taker 费率 0.05%；滑点对前 50 流动性的币取 5bp 量级 — 备选：按成交额/ADV 建模冲击成本（更真实，但需要额外参数）。
- **资金费 = 当天开始时的持仓名义价值 × 当天结算费率之和；多头在正费率时付费** — 简单、可手算；与按每次结算时标记价格计算的差别是二阶小量 — 备选：拆成每 8 小时记账（需要小时线价格）。
- **持仓标的连续 3 天无价格即按最后价格强制平仓并计成本** — 模拟下架结算；只依赖"已经连续 3 天没报价"这一过去信息，不偷看未来是否会下架 — 备选：提前知道下架日（前视）。
- **默认在信号当天收盘成交（execution_lag=0），可配置延迟** — 与 IC 评估的时点一致；延迟成交用于检验信号对执行速度的敏感性 — 备选：默认延迟 1 天（更保守）。
- **多空组合：最高组做多、最低组做空、各 50% 名义（美元中性）** — 剥离市场方向，收益来自选币能力 — 备选：只做多最高组。
- **夏普不扣无风险利率；年化按 365 天** — 加密市场 7×24 交易，USDT 无统一的无风险利率 — 备选：扣除 USDT 理财利率。
- **调低合成数据的植入信号强度（反转 0.025、动量 0.02、资金费 0.03）** — 初版反转因子扣成本后夏普约 5，远不真实，会误导学习 — 备选：保持原值。
